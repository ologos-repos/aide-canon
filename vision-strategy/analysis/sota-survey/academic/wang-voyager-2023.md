# Academic — Voyager (Wang et al., 2023)

> SOTA-survey finding (academic slice). Shape per [`../README.md`](../README.md) → [`sota-survey/README.md`](../../sota-survey/README.md). **Positioning note:** this is a *lineage* entry, not a competitor entry — Voyager is upstream research the canon **builds on**, so the dominant relation is *canon builds-on / adopts*, not *AIDE ahead/behind*. Cadence: **slow** (a published, stable 2023 paper; revisit only if the authors ship a successor or the canon's Skill↦Means treatment changes).

## 1. What it is

**Voyager** is the first LLM-powered embodied *lifelong-learning* agent: it plays Minecraft open-endedly, continuously exploring, acquiring new behaviors, and making discoveries without human intervention or a fixed task. It has three components: (1) an **automatic curriculum** that proposes progressively harder objectives to maximize exploration; (2) an **ever-growing skill library** of *executable code* — each mastered behavior is stored as a callable program, retrieved and composed for later, harder tasks; and (3) an **iterative prompting mechanism** that folds environment feedback, execution errors, and **self-verification** back into the program until it works. Its load-bearing idea for the canon is **"skills as reusable programs"**: skills are temporally-extended (a program spans many primitive actions), interpretable (they are readable code), and compositional (programs call earlier programs), and the library is durable across the agent's lifetime. Empirically Voyager unlocked the Minecraft tech tree far faster than prior LLM agents (≈3.3× more unique items, 2.3× longer traversal) and transferred its learned skills zero-shot to novel worlds.

**Full citation:** Guanzhi Wang, Yuqi Xie, Yunfan Jiang, Ajay Mandlekar, Chaowei Xiao, Yuke Zhu, Linxi Fan, Anima Anandkumar. *Voyager: An Open-Ended Embodied Agent with Large Language Models.* arXiv:2305.16291 (submitted 2023-05-25; v2 2023-10-19). Published in **Transactions on Machine Learning Research (TMLR)**, 2024. NVIDIA / Caltech / UT Austin / Stanford / UW-Madison.

### Terminology note (canon vocabulary discipline)

- **"agent" → AI-aide.** Voyager calls its system an "embodied agent." In canon prose this is an **AI-aide** ([ADR-EA-0016](../../../../decisions/ADR-EA-0016-adopt-ai-aide-as-canon-vocabulary.md)) — though Voyager is a notable boundary case: it has **no principal** (it runs open-endedly with no human in the loop), so it is an *autonomous agent in the literal sense*, not an AI-aide-under-a-principal. That absence is the governance gap §4 turns on. The OAgents `Agent` (a typed object inside a behavioral envelope) is a *different* sense again — do not conflate Voyager's "agent" with either.
- **"skill" → MxM Means (a Skill at the execution surface).** This is the load-bearing mapping. Voyager's "skill" is a *reusable program*; the canon adopts that exact sense for what a **Skill** is at the **Means** surface. **Term-seed flag:** Voyager is the upstream coinage the canon's Skill primitive descends from — record it as lineage, not collision. (Contrast the vendor field, where LangChain's "Skill" = a *knowledge package* — a different sense that *does* collide; see [`../vendor-stacks/langchain.md`](../vendor-stacks/langchain.md) §3.)
- **"tool"** — Voyager's primitives (the Mineflayer API calls its programs invoke) are **Tools** in the canon's atomic sense; convergent across the field.
- No Ologos-ecosystem / NG-AIDE-01 conflation is at issue in this entry; Voyager is external research and no canon *deployment* is named here.

## 4. Position / relationship

**Headline: the canon builds on Voyager for the Skill primitive.** Voyager is the **top of the lineage** for the Skill↦Means distinction — "skills as reusable programs" is the academic origin that the canon's Means treatment (and the ng-aide-01 §5.1 ontology) adopts as its referent. Per-contribution:

- **Skill-as-program → canon adopts (lineage origin).** The canon does not claim this idea; it inherits it and re-homes it under governance. Voyager establishes *what a skill is* (a temporally-extended, interpretable, compositional program); the canon establishes *where it sits and what governs it* (the **Means** surface — which *implements* and does not *permit*; permission is Morals). This is a clean builds-on, not an ahead/behind.
- **Skill library → canon builds-on.** Voyager's self-growing library is the academic exemplar of a durable capability store (Means persisted via Memory). The canon's `practice → method → moral → means` graduation pipeline is the *governed* counterpart of Voyager's admit-after-verify loop — the canon adds the curation/enforcement Voyager's autonomous admission omits.
- **Automatic curriculum → AIDE ahead on governance.** Voyager's curriculum is a working autonomous prep/pivot loop with **no human-curation inflection** — exactly the ungoverned agent loop [AIDK](../../../../foundation/aidk/) flags as a liability and [prep-pursue-pivot](../../../../patterns/prep-pursue-pivot.md) governs (prep's APPROVE gate, pivot's GOVERNED DECISION). The canon has the vocabulary and the governance gradient Voyager lacks.
- **Self-verification → in flight elsewhere; canon builds-on the mechanism, replaces the certification.** Voyager's decoupled self-verifier matches prep-pursue-pivot's required evaluator-decoupling, but it is a *sibling-model* self-certification — the [EIF §8](../../../../patterns/epistemic-integrity-floor.md) "EIF cannot self-certify; external validation closes the loop" critique applies directly. The canon keeps the decoupled-evaluator mechanism and substitutes an *external* validation regime (controlled comparison / primary-source check / **HCAE** review).

**Synthesis.** Voyager is the **purest open-research realization of "skill as reusable program," and the cleanest worked example of why that idea needs the governance the canon supplies.** It proves the Means-layer primitive empirically (zero-shot skill transfer, self-growing library) while running entirely *without a principal* — no HCAE gate, self-certified completion, self-directed curriculum. The canon is precisely the layer that takes Voyager's Skill primitive and binds it to a principal: Means holds the skill, Memory persists the library, prep-pursue-pivot governs the curriculum-and-verify loop, EIF replaces self-verification with an external loop, and OrdSA/Morals supply the authority Voyager has no need for because it answers to no one. They **compose along the lineage axis**: Voyager originates the capability primitive; the canon governs it.

## 5. Objective implication

Doerr-style Objective shapes this finding informs:

1. **Defend-and-extend (governance over the Skill primitive).** *Objective: establish AIDE as the governance layer over self-growing skill libraries.* Voyager is the canonical proof that the Skill-as-program primitive works *and* that it ships ungoverned. KR shape: a documented "govern-a-Voyager-class-skill-library" mapping — Means as the store, Memory as the lifetime persistence, the `practice → method → moral → means` graduation as the *governed* admission gate replacing Voyager's autonomous admit-after-self-verify.
2. **Catch-up / converge (external verification over self-verification).** *Objective: make decoupled evaluation external-by-default across AIDE skill admission.* Voyager's self-verifier is the named anti-pattern EIF §8 exists to correct. KR shape: an exemplar that admits a skill to the library only after an *external* validation regime fires (controlled comparison or HCAE review), not a sibling-model self-check — closing the self-certification gap on a working skill-library implementation.
3. **Defend-and-extend (curriculum under HCAE).** *Objective: name and govern the autonomous-curriculum loop.* KR shape: map Voyager's automatic curriculum onto prep-pursue-pivot with the dialable autonomy gradient made explicit — demonstrate the same self-exploration with a human-curation inflection at prep (plan approval) and pivot (course-change), proving the governance gradient costs little capability.
